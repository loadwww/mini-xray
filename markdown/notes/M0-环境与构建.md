# M0 · 环境与构建

### 1. `cmake -S . -B build` 之后，`build/` 里多了什么？谁生成的？

- 多的是**构建系统自己的文件**：`CMakeCache.txt`（配置缓存）、`CMakeFiles/`、生成器产物（Ninja 是 `build.ninja` + `rules.ninja`，VS 生成器是 `.sln` + `.vcxproj`）
- 生成者是 **CMake**，不是编译器。这一步还没编译任何代码
- 分两阶段：**配置期**（读 `CMakeLists.txt` → 探测编译器 → 生成构建文件）、**构建期**（`cmake --build` 调 ninja/MSBuild 真正编译链接）
- 所以 `CMakeLists.txt` 改了就重新配置，只改 `.cpp` 直接 `--build` 就行

### 2. 为什么头文件里通常只放声明？

- 头文件会被 `#include` 到**多个** `.cpp` 里，内容复制多份
- 函数声明复制多份没问题（声明可以重复，链接期只找一份定义）
- 定义复制多份 → 每个 `.obj` 都产出一份同名符号 → 链接期 **LNK2005 重复定义**
- 例外：`inline` 函数、模板、`class` 内定义的成员函数——它们允许重复定义（链接器按 COMDAT 合并）
- 变量定义放头文件也是同一个雷（`int stand = 1;` 那种）

### 3. `#include "x.h"` 和 `<x.h>` 的区别？

- 只差**搜索起点**：`""` 从"包含它的那个文件所在目录"开始找，`<>` 跳过这一步，直接去系统/指定的 include 目录
- 工程约定：自有代码用 `""`，外部依赖和标准库用 `<>`——让读者一眼看出这行依赖来自项目内还是项目外
- 两者都不影响链接，纯粹是查找路径的差别

### 4. Debug 和 Release 的产物为什么不能混用？

- 两套 CRT（`/MD` vs `/MDd`）各有一份堆，内存从一个堆分配、丢给另一个堆释放 → 崩
- `_ITERATOR_DEBUG_LEVEL` 不同 → STL 容器**内存布局都不一样**，一个 TU 按 Debug 布局解释 Release 造的 `std::string` → 直接读垃圾
- 链接器会拦一部分（`LNK2038` 运行时不匹配、`LNK4098` 库冲突），但拦不全，最稳的是**obj 和 lib 一起重编**

### 5. 什么是编译单元？一个 `.cpp` 加上它 `#include` 的所有头文件叫什么？

- **翻译单元（TU）= 一个 `.cpp` + 它（递归）包含的所有头文件**，预处理后展开成一个大源文件，编译器一次看的是这个整体
- 编译器**看不到**别的 `.cpp`，所以一个 TU 里只能看到声明；定义在别处的符号交给链接器拼
- 推论：头文件里的 `#pragma once` 只防"同一个 TU 内重复包含"，防不了"多个 TU 各包含一份"——那是链接期的事
