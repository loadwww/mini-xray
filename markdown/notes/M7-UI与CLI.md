# M7 · UI 与 CLI

### 1. 内嵌 HTML 的代价是什么？什么时候应该改成外置资源？

- 收益是**单文件分发**：拷一个 exe 就能用，没有静态目录、没有 CDN、离线可跑
- 代价是 HTML/JS 改动必须重编译，源码里塞大段 raw string 会让 C++ 文件臃肿，编辑器也缺少语法高亮
- 判据：页面小、迭代慢、要求零部署 → 内嵌；页面复杂、前后端分工、需要热更新 → 外置资源 + 明确版本配对
- 折中做法：HTML 字符串独立成一个 `.cpp`（`webui_assets.cpp`），与路由逻辑分开，至少让改动范围可控

### 2. 为什么这里用轮询而不是 SSE 推送给前端？

- 数据源是**磁盘上的文件**，不是内存事件流：文件追加没有天然订阅机制，要推送得再搭一层跨进程/跨线程的事件总线
- 3 秒轮询对"人看报告"这个场景足够，实现简单、无连接状态、断线自动恢复、服务端无背压问题
- 代价是延迟和额外请求；判据是**更新频率低 + 用户能接受秒级延迟 + 正确性要求高于实时性**
- 反过来，如果要求毫秒级刷新或有大量客户端，轮询的放大效应就不可接受——那时才值得上 SSE/WebSocket

### 3. CreateProcess 和 fork+execve 在"继承环境变量"上有什么差别？

- POSIX `fork()` 复制整个地址空间和环境，随后 `execve()` 需要显式传 `envp`；不传就继承父进程的
- Windows 没有 fork，`CreateProcessW` 支持传 `lpEnvironment` 指向一整块 `KEY=VALUE\0...\0` 的Unicode 环境块；不传则继承
- 要"注入一个变量而不破坏其他变量"，Windows 只能自己遍历 `GetEnvironmentStringsW` 复制并追加/覆盖，再构造连续内存块
- 判据：**子进程配置优先走环境变量而不是改 agent 源码**——零侵入、语言无关、随时可撤；代价是进程级全局、无类型校验

### 4. Ctrl+C 时进程会收到什么？怎么保证不丢数据？

- Windows 控制台收到 `CTRL_C_EVENT` / `CTRL_BREAK_EVENT`，由 `SetConsoleCtrlHandler` 的回调处理；POSIX 是 `SIGINT` / `SIGTERM`
- 信号/回调里只能做**异步信号安全的最小动作**：置一个 `std::atomic<bool>` 标志，不做 I/O、不加锁、不分配内存
- 真正的工作在监听线程/观察线程里做：置标志 → 调 `svr.stop()` → listen 返回 → Recorder flush 排空队列 → join 所有线程 → 最后 finalize
- 判据：**优雅退出是一条有序的关闭链**，不是"收到信号就 return"；顺序错了就会丢最后几个事件或留下半截文件

### 5. diff 两个 run 时，"对齐"为什么不能用时间戳？

- 时间戳受机器负载、时钟调整、网络抖动影响；同一步在不同运行里绝对时间必然不同
- 应该用**逻辑序号**（第几轮模型调用、第几个工具）作为对齐键，时间戳只用来展示耗时差异
- 判据：比较"结构是否相同"用序号和标识，比较"性能是否变化"才用时间；混用会把噪声当成语义差异

### 6. 路径穿越防护的判据是什么？

- 不是"字符串里没有 `..`"，而是**解析后的真实路径必须是允许根目录的直接子项**
- 先拒绝绝对路径和分隔符（含 Windows 反斜杠），再用 `weakly_canonical` 消解符号链接与相对段，最后检查 `parent_path() == root`
- 判据：**用规范化后的结果做判断，不用原始输入做字符串黑名单**；黑名单永远漏变体（编码、分隔符、符号链接）
