# Markdown 表格与文本转义速查（T6.3）

只放语法与原型，不放实现。

## 表格语法

```markdown
| 列1 | 列2 |
|---|---|
| 值1 | 值2 |
```

- 第二行 `|---|---|` 是**表头分隔行**，列数必须与表头一致，否则渲染器不认这是表格
- 每行以 `|` 开头结尾，单元格内容两侧留一个空格是可读性惯例，不是语法要求

## 单元格里必须转义的三个字符

| 原字符 | 写成 | 原因 |
|---|---|---|
| `\|` | `\\|` | 会被当成列分隔符 → 列数错位、表格破版 |
| 反引号 `` ` `` | `` \` `` | 会开启/关闭行内代码，破坏后文渲染 |
| 换行 `\n` / `\r\n` | `<br/>` 或空格 | 表格行不能跨物理行，换行会截断表格 |

转义顺序：先处理反斜杠相关的，再处理 `|` 和换行。逐字符扫描天然安全。

多行折叠成单行：把 `\r\n` / `\n` / `\r` 都替换成 `<br/>`（保留分行语义）或空格（纯折叠）——
本关工作单说"多行折叠成单行"，两种都可，选 `<br/>` 更可读。

## 字符串截断（按字符数，不是按字节）

```cpp
const std::size_t kMax = 200;
std::string brief = s.size() > kMax ? s.substr(0, kMax) + "..." : s;
```

C++17 的 `std::string::size()` 是**字节数**。UTF-8 中文一个字 3 字节——
按 200 截可能切在字中间，产生非法 UTF-8 → 渲染器显示乱码。
本关简化：验证台用 ASCII 结果测截断；若要正确处理中文，需按 UTF-8 码点边界回退
（原项目有 `utf8Truncate` 做这件事）。这是"诚实的 Limitations"素材。

## 空值统一表示

空字段一律写 `—`（U+2014 em dash），不要写：
- 空字符串 → 表格里看起来像漏了一格
- `null` / `N/A` → 让不懂 JSON 的人困惑
- `0` → 与"真的是 0"混淆（这正是 `Usage::observed` 要解决的问题）

## 本关函数

```cpp
// src/ui/report.h
std::string emitReport(const Run &run);
```

纯函数：只读 Run，返回字符串。不碰文件系统、不碰 HTTP、无全局状态。
T6.2 的 finalize 负责把它写进 report.md——职责分离让本关可用纯字符串测试。

## 失败信息前置的结构理由

读者扫报告的顺序是"标题 → 第一屏"。若失败信息埋在第 8 步的章节里，
读者要滚动才能发现。所以：
1. 标题下第一句 = 一句话结论（成功 / 第几步开始出问题）
2. 概览表之后 = 最早失败的详情
3. 然后才是按步展开的正文

这是"给用户想看的东西，按他看的顺序排"——不是按数据产生的顺序排。
